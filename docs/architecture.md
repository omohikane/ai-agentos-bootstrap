# Architecture

ai-agentos-bootstrap declaratively builds "a VM where an AI agent can work
autonomously" on top of vanilla Arch Linux. It does not build a custom OS; it
combines Arch Linux + cloud-init + Ansible.

## Layers

```
┌──────────────────────────────────────────────────────────┐
│ [4] AI agent runtime layer      (Phase 2)                 │
│     opencode / claude code / codex, ...                   │
│     per-agent config generated from ansible/config/      │
├──────────────────────────────────────────────────────────┤
│ [3] Configuration layer         ansible-playbook (localhost)│
│     base → tools → ai → security                          │
│     user edits vars/tools.list and vars/ai-tools.list     │
├──────────────────────────────────────────────────────────┤
│ [2] Minimal core                bootstrap.sh (shell)      │
│     git, base-devel, ripgrep, ansible, python, uv,        │
│     rustup, fnm (Node), yay — fixed and minimal           │
├──────────────────────────────────────────────────────────┤
│ [1] Vanilla layer               cloud-init template       │
│     username + SSH key injected → boots login-ready       │
│     (qcow2 generated locally by build-image.sh)           │
└──────────────────────────────────────────────────────────┘
```

## Design decisions

- **Fully declarative**: no prebuilt template is distributed. The qcow2 is
  generated locally by `build-image.sh` from declarative definitions, so the
  recipe itself is the OSS value.
- **bootstrap.sh stays small and fixed**: it only installs the core toolchain.
  Everything more complex is delegated to Ansible.
- **Ansible is a self-apply**: it targets localhost. Runs automatically on first
  boot and can always be re-run manually (`make provision`). Idempotency is a
  requirement.
- **AI tools are an opt-in list**: `ai-tools.list` toggles opencode / claude
  code / codex, etc. Installed tools get per-agent dotfiles generated from
  `ansible/config/<tool>/` (Jinja2 templates). Master settings live in the
  repository and are applied per agent.
- **Secrets are injected, not committed**: a `.env` file is generated by
  cloud-init (user-data) from an example template. The project assumes
  disposable VMs and short-lived tokens; see docs/usage.md.
- **Security is pragmatic**: SSH key-only login, passwordless sudo, no firewall
  hardening beyond defaults, no automatic package updates. A broken VM is simply
  rebuilt.

## Execution flow

```
build-image.sh ──► qcow2 (cloud-init enabled) ──► import to Proxmox / KVM
                                                        │ user-data: user + SSH key + .env
                                                        ▼
                                                  first boot
                                                        │ cloud-init runcmd
                                                        ▼
                                          clone repo → bootstrap.sh → make provision
                                                        ▼
                                     base → tools → ai → security (idempotent)
                                                        │
                                                        ▼
                                     agent-ready VM (login with SSH key)
```

## Concerns and future work

- **Arch Linux is a rolling release**: reproducibility is inherently weaker.
  CI generates and validates from the current snapshot; a second validation
  target (e.g. Fedora) is a possible future addition.
- **Phase 2 is the differentiator**: autonomous agent execution (opencode --auto
  or manual invocation of opencode / claude code / codex) plus a rebuild recipe
  is what makes this "AI-agent-specific" rather than a generic dotfiles repo.
